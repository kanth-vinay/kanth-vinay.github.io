Self-hosted Moodle · AWS · Cloudflare
The Goal

ActiveSTEM Online is the self-hosted, self-owned course platform underneath ActiveSTEM's math cohorts — built so that student data, course content, pricing, and the underlying software all stay under your control rather than a vendor's, while being lean enough for one person to build across a handful of weekends and cheap enough to be viable at boutique-cohort scale.

The deeper goal sits underneath that: build something that behaves like Khan Academy's care-first ethos and IXL's rigor, explicitly not like a high-volume enrollment funnel — while staying architecturally sound enough that it could plausibly support a future institutional relationship (a DESE-type partnership) without a rebuild.

How to use this document

This is a living document, not a one-time build log. It's meant to stay accurate for as long as ActiveSTEM Online runs — when a component changes (a new instance size, a new plugin, a different backup schedule), this page should be updated to match, so it stays trustworthy as the map rather than becoming a record of how things used to work.

Work through the five weekends in order the first time. After that, use the sidebar as a reference: jump straight to the section that matches whatever you're touching.

Prerequisites (MacBook Pro)

Since you are managing this entirely yourself, your MacBook Pro is your command center. You don't need heavy DevOps software, but you must have these specific tools installed before starting Weekend 1.

Required software (free)
1. Code Editor: Visual Studio Code

Do not use Mac TextEdit for writing scripts. TextEdit quietly injects hidden "smart quotes" and formatting characters that will completely break Linux bash scripts and Moodle config files. Download VS Code (free) and use it exclusively when saving backup scripts or CSS.

2. Dedicated Password Manager

You will generate an AWS Root account, an IAM admin account, Cloudflare credentials, a Moodle admin account, and a database password. Do not reuse passwords across these boundaries. Use 1Password or Bitwarden.

3. Authenticator App (MFA)

AWS requires Multi-Factor Authentication. A root AWS account without MFA is an immediate, catastrophic security risk. Have Google Authenticator, Authy, or 1Password's built-in authenticator ready on your phone/Mac.

4. Terminal (Already installed)

Press Cmd + Space and type "Terminal". You will need it in Weekend 1 to connect to the server for the first time using the .pem file AWS gives you. After Weekend 2, you'll use AWS Systems Manager instead, but Terminal is required for the initial setup.

"Uploading" Moodle — What an AMI really is

This is the most common conceptual hurdle: you never download a Moodle installer, and you never upload any files to AWS to make it appear.

An AMI (Amazon Machine Image) is a complete, frozen snapshot of a computer's hard drive — operating system, installed software, configuration files, all of it. Launching an EC2 instance "from" an AMI means AWS copies that entire snapshot onto a new virtual machine and boots it up.

The Bitnami Moodle AMI is maintained by VMware. It provides a Linux server with a web server, PHP, MySQL, and Moodle pre-wired. When you launch it in Weekend 1, AWS boots a virtual computer from that exact snapshot. The moment it finishes booting (~3 mins), Moodle is live.

Where a login, an answer, and a grade go

Walking one real action all the way through the stack above, start to finish:

1. Student opens learn.activestem.org and enters a passwordThe browser sends this over an encrypted connection to Cloudflare, which forwards it on to your EC2 instance.
2. The web server (Apache) receives itIt sees the request is for a PHP application and hands it to Moodle's code. Apache itself doesn't understand Moodle, it just routes traffic.
3. Moodle checks the password against MySQLMoodle's PHP code looks up that email in the mdl_user table and compares the (encrypted) password.
4. The student's dashboard loads from MySQLWhich courses they're enrolled in, current grades — all pulled live from the database on every page load.
5. Student answers a hint-based problemThe moment they submit, Moodle writes that attempt straight into MySQL — which page, what they answered, right/wrong.
6. The gradebook updates instantlyBecause the gradebook isn't a separate system — it's a view Moodle generates by reading the same MySQL tables.
7. Once mastery is met, the certificate plugin firesIt reads the gradebook, generates a PDF, saves it into the moodledata folder (a file, not a database row), then emails it via SES.
8. That night, both halves get backed upThe nightly cron job copies the MySQL database and the moodledata folder to S3. Both are required for a complete restore.

Weekend 1 · AWS Core 4–6 hrs

Goal: End this weekend with a running server that only you can access.

1. Create the AWS Account

Go to aws.amazon.com and click Create Account. Use a dedicated business email, not a personal/university one. AWS requires a credit card; this pilot scale will cost a few dollars initially.

2. Lock the Root Account with MFA

Don't: Leave the Root account unprotected

The account you just created is the "Root" user. It can delete the entire business. You must immediately enable MFA (via your Authenticator app) on this Root account. Go to IAM -> Add MFA.

3. Create an IAM admin user

Create a new User (e.g., `vinay-admin`) in the IAM dashboard, grant it `AdministratorAccess`, enable MFA on it, and log out of Root forever. Do all subsequent work as the IAM user.

4. Launch the Bitnami Moodle Instance

a. Find the image: In the AWS Console, go to EC2 → Launch instance. Search Bitnami Moodle. Switch to the AWS Marketplace AMIs tab. Select the official Bitnami package (free software).

b. Instance Type: Choose t3.small (2 vCPU, 2GB RAM). This handles 4-10 concurrent active users easily.

c. Key Pair: Click "Create new key pair" (RSA, .pem), name it, and download it. Store it in 1Password. You will need this file in step 7.

d. Storage: Change the default 20GB `gp2` to 30GB `gp3`. `gp3` is faster and significantly cheaper per month.

e. Launch: Click Launch. Wait 3-4 minutes. Copy the Public IPv4 address into your browser. You should see the default Moodle landing page.

5. Configure the Security Group (The Locked Door)

In the instance's Security Group (Inbound Rules), allow only these ports:

  • Port 443 (HTTPS): Source 0.0.0.0/0 (Anywhere)
  • Port 80 (HTTP): Source 0.0.0.0/0 (Needed for initial SSL, then redirects)
  • Port 22 (SSH): Source My IP (Temporarily needed, will close next weekend)

6. Attach an Elastic IP

In EC2, go to Elastic IPs and Allocate a new IP, then Associate it to your instance. This prevents the server's IP from changing if it reboots.

7. Critical: Create the Swap File

Do: Create a 2GB Swap File before doing anything else

A `t3.small` has 2GB of RAM. If several students submit a complex math quiz simultaneously, PHP can briefly spike memory usage. If Linux runs out of RAM, it instantly terminates MySQL and crashes your site. A Swap file borrows 2GB of your hard drive to act as slow emergency RAM, preventing crashes.

First, connect to your server. Because you haven't set up browser-based access yet, you must use your Mac's Terminal and the `.pem` file you downloaded in step 4.

Open Mac Terminal (Cmd + Space, type "Terminal"). Run these commands to secure your key and connect (replace YOUR_ELASTIC_IP with your server's IP):

cd ~/Downloads chmod 400 your-key.pem ssh -i "your-key.pem" bitnami@YOUR_ELASTIC_IP

Type "yes" when asked if you want to continue. You are now inside the server as the `bitnami` user.

Now, create the swap file: Paste these commands line-by-line:

sudo fallocate -l 2G /swapfile sudo chmod 600 /swapfile sudo mkswap /swapfile sudo swapon /swapfile

Make it permanent across reboots by adding it to fstab:

echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

Confirm it is active with free -h. The Swap row should show a non-zero number (e.g., 2.0G). You can now type exit to leave the server.

Weekend 2 · Edge & Access 2–4 hrs

1. Cloudflare DNS Configuration

Create a free Cloudflare account. Add activestem.org. Cloudflare will provide two nameservers — log into your domain registrar (e.g., Namecheap, Route53) and replace the existing nameservers with Cloudflare's.

2. Point subdomain at the server

In Cloudflare's DNS tab, add an A Record named learn pointing to your AWS Elastic IP. Ensure the orange "Proxy" cloud is turned ON.

3. Turn on SSL (Full)

Warning: SSL Mode must be "Full", not "Strict"

Go to Cloudflare -> SSL/TLS. Set it to Full. Bitnami generates a self-signed SSL cert on the AWS server. Cloudflare's "Full" mode encrypts the traffic but ignores the self-signed warning. If you choose "Full (Strict)", Cloudflare will reject the AWS server and your site will break.

4. AWS Systems Manager (SSM)

Leaving port 22 (SSH) open to the internet is a massive vulnerability. We will replace it with browser-based SSM so you never have to use the Mac Terminal or the `.pem` file again.

In AWS IAM, create a Role for an AWS Service (EC2) and attach the AmazonSSMManagedInstanceCore policy. Go to your EC2 instance -> Actions -> Security -> Modify IAM Role, and attach this new role. Wait 5 minutes.

You can now click Connect → Session Manager in the EC2 console to get a secure terminal right in your browser.

Crucial Final Step: Edit your EC2 Security Group and delete the Port 22 SSH rule entirely.

Weekend 3 · Course Build 4–8 hrs

1. Secure Admin Login

Select your instance in AWS, click Actions → Monitor and troubleshoot → Get system log, and scroll until you see a box containing the application password. Log into Moodle with username `user` and this password. Immediately change the password in Moodle preferences. Navigate to Site Admin → Security → Multi-factor authentication and enforce it for admin roles.

2. Apply Brand Theme

Go to Site administration → Appearance → Themes → Boost (or whatever default theme is active). In the settings tabs for the theme, apply your exact brand tokens in the SCSS or color options: #1D2C48 (Navy), #2C5545 (Green), #B58D3D (Gold). Upload a crisp SVG logo.

3. Course Shell Setup

Go to Site administration → Courses → Add a new course. You must fill out three required fields before Moodle lets you save:

  • Course full name: Extreme Algebra
  • Course short name: ExtAlg (This is used in the top breadcrumb navigation).
  • Course format: Set this to "Topics format" to match your unit structure.

Hide all unused blocks (calendar, online users) to keep the UI clean.

4. Build Hint-based Lessons

Do: Use the "Lesson" Activity for Hints

Instead of standard Quizzes, use the Lesson activity to mirror your A/B/C variant approach. Go to your course page, click Turn edit mode on (top right toggle), click Add an activity or resource, and select Lesson. Structure it: Problem Page -> Student inputs answer. If correct -> jumps to next concept. If wrong -> jumps to a specific Hint Page -> loops back to question.

5. Certificate Plugin

Install the "Custom certificate" plugin via Site administration → Plugins → Install plugins. Restrict it so it only unlocks when a passing grade is achieved in the Gradebook.

6. Critical: Verify Moodle's own cron

Warning: Emails won't send without Cron

Even if SES is perfect, Moodle queues emails and waits for its internal "cron job" to trigger the actual send. If cron is broken, no emails or certificates go out.

Go to Moodle Site Admin → Server → Tasks → Task logs. Look at the "Last run" column. If it says "Never", your cron is broken.

Open an SSM browser terminal. Bitnami runs the Moodle cron under either the bitnami or daemon user depending on the version.

Check both: sudo crontab -l -u bitnami and sudo crontab -l -u daemon.

Confirm one of them has a line executing admin/cli/cron.php every minute (* * * * *). If neither does, you must manually add it via sudo crontab -e -u daemon.

Weekend 4 · Comms & Cash 4 hrs

1. Stripe Payment Link

Go to Stripe and create a Product ($50). Generate a Payment Link. You don't need APIs or webhooks right now — when a parent pays via this link, you manually enroll the student in Moodle (a 60-second task).

2. SES Outgoing Email

Moodle must send password resets and certificates. AWS SES is the cheapest and most reliable way to do this.

a. Verify Domain: In AWS, go to Amazon SES -> Verified Identities -> Create Identity (Domain: activestem.org). AWS gives you 3 CNAME records.

b. Connect Cloudflare: Open Cloudflare DNS and add all three CNAME records. Wait 5 mins for AWS to verify.

c. Request Production Access: You start in a "Sandbox". Fill out the AWS form requesting production access (takes ~24h to approve).

d. Configure Moodle: Once approved, generate SMTP credentials in SES and paste them into Moodle's Site Admin -> Server -> Email -> Outgoing mail configuration.

3. Set up a support channel

A Moodle course forum is the simplest option for async questions. Post a standing Zoom link for optional office hours on the homepage.

4. Write the terms & privacy page

Cover what data you collect, your refund policy for the pilot, and confirmation that a parent or guardian completes enrollment for minors.

Weekend 5 · Safety Net 3 hrs

1. Automate S3 Backups

If your EC2 disk corrupts, you lose the database. You must backup to S3 nightly.

a. Prepare AWS: Create an S3 bucket (e.g., activestem-backups-2026). In IAM, attach the AmazonS3FullAccess policy to the EC2 instance's role.

b. Verify AWS CLI & Get DB Password: Open an SSM terminal. Ensure AWS tools are installed by typing aws --version. Next, Bitnami auto-generates the database credentials. Find them by running:

sudo cat /bitnami/moodle/config.php | grep -E "dbuser|dbpass"

c. Create Script: In the terminal, run nano /home/bitnami/backup.sh (you are already the `ssm-user` or `bitnami` user, so this creates it in your home folder) and paste:

#!/bin/bash DATE=$(date +%Y-%m-%d) BUCKET="s3://YOUR_S3_BUCKET_NAME" DB_USER="YOUR_DB_USER" DB_PASS="YOUR_DB_PASSWORD" # 1. Dump MySQL Database mysqldump -u $DB_USER -p$DB_PASS bitnami_moodle > /tmp/db_$DATE.sql # 2. Compress moodledata folder (using sudo to avoid read errors) sudo tar -czf /tmp/data_$DATE.tar.gz /bitnami/moodle/moodledata # 3. Copy to AWS S3 aws s3 cp /tmp/db_$DATE.sql $BUCKET/ aws s3 cp /tmp/data_$DATE.tar.gz $BUCKET/ # 4. Clean up temp files rm /tmp/db_$DATE.sql /tmp/data_$DATE.tar.gz

Save (Ctrl+O, Enter) and Exit (Ctrl+X). Make it executable: chmod +x /home/bitnami/backup.sh

d. Automate it: Run crontab -e (just that, no `sudo`, so it runs as your current user) and add: 0 2 * * * /home/bitnami/backup.sh (Runs at 2:00 AM daily).

2. The Restore Test

Don't: Assume backups work without testing

A backup you have never restored is just an assumption. Launch a blank EC2 instance, practice pulling your `.sql` and `.tar.gz` files from S3 and importing them. Document exactly how long it takes.

3. Uptime Monitoring

Create a free account at UptimeRobot. Point it at learn.activestem.org to get emailed if the server drops.

4. Write a one-page runbook

Document how to restore from S3, the monthly maintenance checklist, and emergency contacts.

5. End-to-end test

Walk through the entire flow as a stranger: pay via Stripe, get manually enrolled, hit a hint, submit, and receive the certificate via SES email.

Glossary

Server & Storage

AWSAmazon Web Services — the landlord you rent computers and storage from.
EC2 instanceThe actual rented computer.
AMI / BitnamiThe frozen template used to boot the EC2 instance. Bitnami configures Moodle, PHP, and MySQL for you.
Web server (Apache)Software that receives requests and routes them to Moodle's code.
PHPThe programming language Moodle is written in.
MySQLThe database holding structured data (users, grades, accounts).
moodledata folderA folder on the disk holding uploaded files and generated certificates.
EBSThe hard drive attached to your instance.
S3AWS's scalable file storage, used purely for holding backup files.

Networking & Access

Security groupA firewall attached to your instance (controlling open ports).
Elastic IPA fixed public address for your instance that survives a reboot.
IAMAWS's permission system (who can do what).
Systems Manager (SSM)Command-line access through your browser, replacing SSH.
Cloudflare / DNSTurns domain name into numeric address, provides free SSL, stops DDoS attacks.
SSL/TLSProduces the padlock icon and "https" — encrypts the connection.

Moodle & Payments

StripeA payment processor. A "Payment Link" is a hosted checkout page.
Amazon SESThe system that actually sends outgoing email (SMTP) out of Moodle.
WebhookAn automatic notification between systems (e.g. Stripe telling Moodle to enroll). Not used at pilot scale.
Cron jobA scheduled task that runs automatically (for backups, or Moodle's email queue).

Security & Compliance (Scaling Up)

Before taking any payment

  • MFA enforced on AWS Root and IAM accounts.
  • Port 22 (SSH) deleted from Security Groups.
  • SSL mode set to "Full" in Cloudflare.
  • Parent/guardian explicitly completes enrollment for minors (TOS check).

Before a second cohort or DESE conversation

FERPA & Institutional Readiness

If approaching a public school system (DESE): FERPA requires "reasonable safeguards," not a specific hosting certification. However, pointing out that your infrastructure lives entirely on AWS (which holds SOC 2 and ISO 27001 certifications) heavily mitigates institutional risk. To be ready, you must document your encryption at rest (AWS EBS encryption), restricted access policies (IAM), and have a written data-retention timeline.

  • A written one-page Runbook exists detailing exact disaster recovery steps.
  • Moodle admin login enforced with Two-Factor Authentication.
  • Course content strictly login-gated, never indexable by Google.

Routine Maintenance

Running a server is not a "set it and forget it" task. Perform these checks via an SSM terminal once a month.

TaskCommand / Action
OS Updatessudo apt update && sudo apt upgrade -y (Patches Linux security holes)
Disk Spacedf -h (Check the / mount. If >85% full, clear logs or expand the EBS volume)
Memory & Swapfree -m (Ensures RAM isn't maxed and the swap file is actively ready to catch spikes)
Backup AuditVisually log into AWS S3 and confirm files with today's date exist. Do not just trust the cron job blindly.

Troubleshooting

  • The site won't load at all (522 Error)

    Check Cloudflare DNS. Does the A record match your EC2 Elastic IP? If you stopped/started the instance without an Elastic IP attached, AWS gave it a new random address. Also check that Cloudflare SSL is "Full", not "Strict".

  • Can't get a Session Manager terminal to open.

    Confirm the IAM role with AmazonSSMManagedInstanceCore is actually attached to the instance (Actions → Security → Modify IAM Role). It can take a few minutes to register after attaching.

  • Emails aren't sending.

    Confirm AWS approved your SES "Production Access" request — until then you're in the sandbox and can only send to verified addresses. If access is approved, check Weekend 3's Moodle cron step — a stuck internal queue looks identical to an SES problem from the outside.

  • The nightly backup didn't run.

    Check the cron job's log output through a Session Manager terminal. Confirm the IAM role attached to the EC2 instance actually has the AmazonS3FullAccess policy to allow writes to the bucket.

  • A Moodle update seems risky to apply.

    Don't just take a manual database backup — go to the EC2 console, select the instance, and click Actions → Image and templates → Create image. This snapshots the entire server, not just the database. If the update breaks the site, you can launch a fresh instance from that exact snapshot in about three minutes.
